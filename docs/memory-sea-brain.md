# 记忆识海 · 大脑形态方案(调研稿,不含实现)

> 状态:调研 + 方案,未写一行实现代码。
> 起因:用户明确否掉了「普通力导向图」——要的是**像大脑一样的神经元**,一个记忆点就是一颗神经元,
> 鼠标放上去能看内容,记忆越多就越像一颗被点亮的、填满的大脑。
> 参考基准:**davidpeled/obsidian-brain-graph**(MIT,TypeScript,three.js)。它就是「笔记=神经元、链接=突触」这件事的完成态,
> 2,569 个节点 / 3,759 条边仍流畅,并且带时间轴回放——正好对上「越来越多、像填满」这个诉求。

## 二、它到底是怎么做的(逐层拆解,全部来自源码)

### 1. 脑壳:24 个控制点 → 侧视轮廓 → 吹成 3D → Marching Cubes

- `src/domain/model/anatomy/brain-anatomy.ts`:矢状面(侧视)大脑轮廓用 **24 个归一化控制点** `CEREBRUM_CTRL` 定义,
  首点在额极 (0.05, 0.5),经顶叶最高点 (0.45, 0.02) 到枕极 (0.97, 0.45),再用 Catmull-Rom 闭合曲线加密。
  小脑 10 点、脑干 8 点各自独立。`BRAIN_WIDTH = 1000, BRAIN_HEIGHT = 760`。
  三条脑沟线(CENTRAL_SULCUS / LATERAL_SULCUS / PARIETO_OCCIPITAL)既是解剖细节,也是**脑叶分界**。
- `src/domain/model/anatomy/brain-volume.ts`:把二维侧视轮廓「吹成」三维——
  轮廓线上厚度为 0,向内部按四分之一椭圆升到 `zmax`;大脑 `{zmax: 0.36, round: 0.24}`、小脑 `{0.26, 0.1}`、脑干 `{0.05, 0.035}`。
  `MIDLINE_GAP = 0.012` 留出纵裂,分出左右半球;`smin()` 平滑并集,避免接缝。
- `src/infrastructure/webgl/brain-mesh.ts`:对上述体素场跑 `MarchingCubes`(three 官方 example)取等值面,
  得到**一个真正的 3D 脑壳网格**;`SHELL_RESOLUTION = { desktop: 128, mobile: 96 }`(96³ 只有 128³ 的 42% 计算量)。
  逐顶点计算所属脑叶 + `BLEND_RADIUS = 0.045` 的混合权重,所以颜色是渐变过渡而不是硬边色块。

### 2. 光:脑壳只亮边缘,神经元是软辉光

- `src/infrastructure/webgl/materials.ts`:`rimMaterial` 做**视角相关边缘光**——脑壳正面几乎透明、只有轮廓发亮,
  这是「玻璃脑」质感的来源;`glowMaterial` 用 ShaderMaterial + `gl_PointCoord` 画软辉光,
  核心 `smoothstep(0.35, 0.0, d)`、光晕 `pow(1.0 - d, 2.2)`,混合色 `mix(tint, white, core * 0.7)`。
- 结论:所谓「神经元」其实**不是模型,是带辉光的点精灵**。这一点很重要——它意味着不需要任何 3D 模型资源。

### 3. 神经元怎么摆:先锚点、再高斯散布、再力导向但**不穿墙**

- `src/domain/model/dynamics/placement.ts`:每个簇先算 anchor(大簇占更中心),节点在 anchor 周围高斯散布,
  `spread = LINK_DIST * (1 + cbrt(clusterSize) * 0.8)`,最多试 30 次直到落在允许区域;
  重建时若旧坐标仍然合法就沿用(视觉连续,不会每次刷新都重排)。
- `src/domain/model/dynamics/layout.simulation.ts`:力导向常量
  `LINK_DIST=30, REPEL_R=64, REPEL_K=55, ANCHOR_K=0.012, VELOCITY_DECAY=0.6, MAX_SPEED=30, ALPHA_DECAY=0.985, ALPHA_MIN=0.004`;
  短程斥力走**哈希空间网格**(三个质数哈希 + 27 邻格),不用 O(n²);
  突触弹簧 `k = 0.5 / max(1, min(degA, degB))`(连接多的节点更"硬");跨脑叶的 tract 只有 `k = 0.004` 的弱拉。
  **最关键的一条**:每个轴的位移分量只有在「目标点仍在允许区域内」时才应用——所以神经元会贴着脑叶内壁滑动,永远不穿出脑壳。

### 4. 活起来:动作电位级联

- `src/domain/model/dynamics/action-potentials.ts`:`MAX_PULSES=700, PULSE_SPEED=150, FAN_OUT=16, PROPAGATE_TO=4, PROPAGATE_P=0.7`。
  触发一个神经元 → 沿最多 16 条突触发射脉冲 → 到达后按 0.7 概率继续传播,形成级联;
  被点亮的节点按 `ACTIVATION_DECAY=2.4` 衰减回暗。
- 这就是「鼠标移上去会亮、会放电」的实现方式,纯前端动画,不依赖任何后端。

### 5. 交互清单(直接可抄)

悬停:高亮该神经元的所有突触 + 持续放电;点击:触发级联 + 打开内容;拖动:在屏幕平面移动但不能离开脑叶;
右键:Open / Fire / Fly to neuron;搜索框:高亮匹配项,Enter 飞到最佳匹配;图例:点击飞到该脑叶;
键盘:方向键旋转、Shift 平移、+/− 缩放、F 适配、R 自动旋转;默认缓慢自转。

## 三、映射到「记忆识海」:我们的数据比笔记更适合这个形态

| 视觉元素 | 参考项目(笔记库) | 我们(巩固层) | 数据位置 |
|---|---|---|---|
| 神经元 | 一篇笔记 | 一条 `ConsolidatedMemory` | `src/consolidated.ts:27-47` |
| 突触 | 笔记间的 wiki 链接 | `LinkGraph` 的一条边(带 weight/label) | `src/consolidated.ts:62` |
| 脑叶 | PARA 四个顶层目录 | `type` 五类:stable-fact / pattern / preference / relationship / mood | `consolidated.ts:24` |
| 脑叶内簇(gyrus) | 子文件夹 | 同一 type 下的语义聚类(用现成 `similarity()` 做连通分量) | `consolidated.ts:94` |
| 亮度/大小 | 链接数(degree) | `touchCount`(被回忆次数)+ `confidence` | 同上 |
| 灰暗/半透明 | 无 | `status = 'dormant'` 变暗; `'superseded'` 变成暗红残影(改口的历史痕迹) | 同上 |
| 时间回放 | 笔记创建时间 | `createdAt` / `lastRecalledAt`,或直接回放审计日志 | `observability.ts:15` |

**这套映射有三点比参考项目更强**:
1. **改口有视觉表达**。参考项目里笔记就是笔记;我们的 superseded 记忆可以留成「暗掉的旧神经元 + 一条指向新神经元的虚线」,
   一眼看出「用户改过口」——这是记忆系统独有的、非常有说服力的画面。
2. **时间回放有真实语义**。不只是「笔记变多」,而是「这段关系是什么时候形成的、哪条记忆什么时候被强化」。
3. **睡眠巩固有节拍**。巩固每跑一轮就是一次「大脑重新长一次」,可以让整颗脑做一次缓慢的呼吸/重排动画。

## 四、技术选型:三条路,代价差很多

| 方案 | 观感 | 体积 | 工作量 | 风险 |
|---|---|---|---|---|
| **A. three.js + MarchingCubes**(照搬参考) | 最接近截图,真 3D、真旋转、真景深 | 打包后 +600KB 左右(进 client.js,不是 npm 依赖) | 4~5 天 | 中:WebGL 在部分环境不可用要降级 |
| **B. Canvas 2D 伪 3D**(预烘焙脑壳轮廓 + 点精灵 + 手写旋转投影) | 静态看很像,旋转时穿帮 | 0 依赖,+30KB | 2~3 天 | 低:兼容性最好 |
| **C. 混合**:Canvas 2D 画脑壳(预烘焙多角度贴图)+ WebGL 点云 | 接近 A,壳略假 | +80KB | 3 天 | 中低 |

**我的建议:B 起步,A 作为 v2**。
理由:① 用户最在意的是「像大脑、能悬停看、会填满」,这三件事 Canvas 2D 都能做到;
② 本插件目前**零运行时依赖**是卖点之一,client bundle 里塞 three.js 会让包从 100KB 涨到 700KB+;
③ 先做 B 能在 2~3 天内让用户看到实物,再决定要不要为「真 3D 旋转」付 600KB 的代价。

无论 A/B,都需要:预烘焙的脑轮廓(可以直接从参考项目的 24 控制点 + Catmull-Rom 生成,数据是 MIT 可借鉴的),
以及**壳内外的位置约束**(节点必须落在轮廓内,否则会飘到脑外,瞬间破功)。

## 五、脑壳从哪来:三条获取路径

1. **抄轮廓点**(推荐):把参考项目的 24 + 10 + 8 个控制点照抄,自己跑 Catmull-Rom 加密成路径。
   优点:体积 0、可任意精度、颜色分区完全可控。缺点:只有侧视一个角度,旋转超过 ±30° 会露出「纸片感」。
2. **程序化噪声生成**:ebcreation-cloud/procedural-brain-threejs(30KB,无模型文件,噪声生成折叠大脑)。
   优点:真 3D 体积;缺点:形状不保证像人脑,需要调参。
3. **下载开源脑模型**(.glb):最真实,但包体积 +2~5MB,且需要 three.js GLTFLoader,与「零依赖」冲突。**不推荐**。

## 六、「越来越多就像填满大脑」怎么实现

参考项目的时间轴已经证明可行,我们只需换成记忆的语义:

- 底部一条时间条 + 播放键,横轴是 `createdAt` 的范围;
- 播放时,神经元按创建顺序逐个「出生」——出生动画是从一个点炸开成带辉光的神经元,同时它连向已有神经元的突触逐条点亮;
- 脑壳透明度随密度变化:空脑时壳很淡(能看清里面空荡荡),填满时壳略微加深、内部辉光把壳照亮(像真的发光);
- 右上角实时显示 `N 个记忆 · M 条联想`,和参考项目的「2569 neurons · 3759 synapses」同款。

**这一点是整套方案的情感核心**:用户第一次打开是空的,用了一个月再打开,脑是满的。这个对比本身就是产品力。

## 十、风格修正(用户 m02219 拍板):**不要壳,要星云**

用户看了截图后明确否掉了脑壳方案:「我感觉不要外面的壳子,像这种,用点和线连接的那种」。

截图里的形态(逐项拆解,这是新基准):

| 元素 | 观察 |
|---|---|
| 背景 | 极深的海军蓝/近黑,**叠一层真实星场**(大小不一的远星,有的亮有的几乎看不见) |
| 主体 | 一团近似球形的点云,约 200~400 个白色发光点,中央更密、边缘更疏 |
| 连线 | 极细的白色线,透明度约 0.15~0.3,连接距离相近的点,有几条长线横穿整团 |
| 文字 | 小号中文字,浮在点旁边,透明度很低,像是「记忆标题」飘在空间里 |
| 配色 | **单色**(白 + 冷蓝白),没有彩色分区 —— 和 brain-graph 的彩色脑叶完全不同 |
| 光 | 中心有一个明显更亮的光点(像被选中的记忆),带柔光晕 |

**结论:这是「深空星图 / 星座」的视觉语言,不是解剖学。**
好处是:① 不需要任何 3D 模型或 Marching Cubes;② Canvas 2D 就能做到 90% 的效果;
③ 单色 + 星场比彩色脑壳更耐看、更像「识海」;④ 包体积增加几乎为零。

### 关键:大脑轮廓从「壳」改成「点云密度」

不要壳,但形状感不能丢。做法是**约束节点生成的体积形状**:把节点撒在一个大脑形状的椭球/双半球体素域里
(可以直接复用参考项目的 `brain-volume.ts` 的 `canOccupy` 判定,只是不画壳)。
于是「大脑」不是画出来的,是**点聚出来的** —— 空的时候是一小团星云,长满的时候自然浮现出大脑的轮廓。
这比画壳高级,也正是用户想要的「记忆越来越多就像填满」。

### 渲染配方(Canvas 2D,零依赖)

1. **底色**:径向渐变 `#05070d → #0a1020`,中心偏亮,模拟深空。
2. **星场**:300~600 颗静态远星,尺寸 0.5~1.5px,透明度 0.1~0.6;加极缓慢的整体旋转(0.02 rad/s)产生视差。
3. **节点**:预渲染一张 64×64 的辉光贴图(径向渐变),每个节点按深度缩放后 `drawImage`,
   合成模式 `globalCompositeOperation = 'lighter'` —— 这是「发光」而不是「白点」的关键。
4. **深度**:每个节点有 z ∈ [-1,1],投影缩放 `s = f / (f + z)`,透明度 `a *= 0.25 + 0.75 * ((z+1)/2)`;
   后面的点更小更暗,自然形成体积感。
5. **连线**:按 z 排序后画,线宽 0.6~1px,透明度 `0.10 + 0.20 * 两端亮度均值`;同样用 `lighter`。
6. **Bloom(廉价后处理)**:整层画到离屏 canvas → 缩到 1/4 尺寸 → 再放大回来 → `lighter` 叠一层,
   得到柔光扩散。这一步是「好看」和「廉价」的分水岭,成本约 2ms。
7. **文字**:只给 `confidence` 或 `touchCount` 最高的前 12 个节点画标签(否则会糊成一片),
   字号 11~12px,透明度 0.45;悬停时该节点的标签升到 1.0 并加描边。
8. **动**:整体缓慢自转 + 每个节点 ±2px 的正弦漂移(相位由 id 哈希决定),画面就「活」了。

### 配色方案(单色为主,极少量语义色)

- 默认节点:`#dfe9ff`(冷白)
- 悬停/选中:`#7fe3ff`(青)+ 光晕放大 2.2 倍 + 沿突触发射脉冲(参考项目的 action potential)
- dormant(沉睡记忆):透明度 × 0.35,颜色偏灰 `#8b95a8`
- superseded(改口旧记忆):`#ff6b6b` 但透明度 0.3,并连一条虚线到新记忆
- 连线:默认 `rgba(190,215,255,α)`,跨 type 的边更暗

### 这套方案对原三问的答案

1. **形态**:确定走 Canvas 2D 星云版(不再需要 three.js)—— 2~3 天出实物,包体积 +30KB 以内。
2. **脑壳**:彻底砍掉。轮廓靠点云密度形成。
3. **数据**:建议「巩固层为主 + 原始碎片为辅」——碎片做成极小极暗的星尘(不参与连线),
   正好充当截图里那层「背景星星」,既壮观又不乱。

## 十一、可执行原型:我已经渲染了一张真图出来(不是示意)

文件:`.refs/mock-starfield-brain.png`(1200×800)。生成脚本:`.mock-render.py`(Python + Pillow,仅用于出图验证观感,不是实现代码)。

这一张是**严格按上面第十节的配方**画的:脑形点云(无壳)+ 深空底 + 700 颗远星 + 300 个节点 + 距离阈值连线 + 深度缩放 + lighter 辉光 + 1/4 分辨率 bloom。
也就是说:**这个观感用 Canvas 2D 能 1:1 复刻**,不需要 three.js,不需要任何模型文件。

### 这张图证明了什么

1. **没有壳,大脑形状依然成立**。因为节点是撒在脑形体积域里的,轮廓自然浮现。填满时会比这张更明显。
2. **单色比彩色高级**。整张图只有白/冷蓝白,反而更像「识海」而不是「数据面板」。
3. **辉光是廉价的**。预渲染一张 96×96 的径向渐变贴图 + `lighter` 合成,300 个节点的开销可以忽略。
4. **bloom 是分水岭**。离屏缩到 1/4 再放大叠回去,2ms 换来的「发光感」超过任何配色技巧。

### 这张图暴露的问题(实现时要修)

| 问题 | 原因 | 修法 |
|---|---|---|
| 现在太「均匀」,像一张网而不是一个脑 | 300 个点均匀撒在轮廓内 | **密度要做出层级**:中心簇密、外围疏;同一 type 的节点聚成「gyrus」小球簇 |
| 连线偏多偏乱 | 纯距离阈值(95px),没有语义 | 连线只走 `LinkGraph` 真实边 + 少量距离补边;跨 type 的边更暗更细 |
| 标签会互相压住 | 12 个标签随机放 | 标签只给 top-N 且做简单避让(同屏最多 8 个),其余悬停才显示 |
| 缺少「活」的感觉 | 静态图 | 加自转 + 每节点正弦漂移 + 选中节点的脉冲沿边传播 |
| 轮廓有点「像花生」 | 侧视轮廓 + 均匀填充 | 加纵裂(中线留空)和脑沟(几条低密度带),轮廓立刻变「脑」 |

### 空 vs 满:这套形态真正的杀手锏

- **第 1 天**:一小团 20~30 个点,周围是深空,像刚点亮的星云。
- **第 30 天**:300+ 个点,脑形浮现,连成一片发光的网。
- **第 90 天**:800+ 个点,脑形饱满,边缘开始有「皮层褶皱」的密度纹理,中心亮成一颗星。

这三张的对比图,比任何文案都有说服力 —— 建议 v1 就把「密度 → 脑形浮现」做成确定性的视觉反馈。

## 十二、成长曲线(用户 m02260 追问):点和线越来越多 → 实体大脑;零记忆时留一个很淡的框架

用户原话:「点和连线肯定是越来越多对吧?最后会越来越密集,像一个实体的大脑?最开始没有记忆的话?可以有一个很淡的大脑框架的那种」。

结论:**完全成立,而且这就是这套形态的主线**。已渲染 6 阶段对照图 `.refs/mock-progression.png`(脚本 `.mock-progression.py`)。

| 阶段 | 节点数 | 画面 | 机制 |
|---|---|---|---|
| 空 | 0 | 深空里一圈**极淡的虚线脑轮廓** + 三条脑沟暗线 + 稀疏内部尘埃 | 框架透明度 0.17,随节点数线性淡出,`a = 0.17 * max(0, 1 - n/140)`,到 140 条完全消失 |
| 初现 | 25 | 十几个亮点 + 少量连线,像刚点亮的星座 | 节点半径大(62px 贴图)、亮度满;连线阈值宽(118px)所以稀疏也连得上 |
| 成网 | 80 | 开始有网状结构,脑形隐约可见 | 框架已淡到 0.07 |
| 浮现 | 200 | 脑形清晰,能看出前后分区 | 节点缩小到 36px、亮度 0.70;连线阈值收到 86px |
| 变厚 | 450 | 皮层出现「厚」的层次,内部透出密集的网 | 节点 27px、亮度 0.55;连线阈值 62px |
| 实体 | 900 | **接近实体大脑**:边缘因为密度自然形成亮的皮层带 | 节点继续缩小,靠 `lighter` 叠加自然饱和 |

### 三个让「越密越像实体」成立的机制(缺一个就散)

1. **节点尺寸随数量反向缩放**(62 → 46 → 36 → 27px),亮度同步下降(1.0 → 0.86 → 0.70 → 0.55)。
   不这么做的话,900 个点会糊成一团白饼,反而失去「实体」的层次。
2. **连线阈值随数量收紧**(118 → 86 → 62px)。不收紧的话,线数按 n² 爆炸,画面会变成灰雾。
3. **色调映射(tonemap)兜底**:最后对整帧做 `255 * (1 - exp(-v/205))`,把密集区的过曝压回来。
   这是「密集但仍有细节」和「密集就一片白」的分水岭——参考项目没有这一步,它靠 3D 景深解决,我们 2D 必须用 tonemap。

### 边缘密度偏置:让脑形「自己长出来」

撒点时按 `rim = min(0.78, n/1100)` 的比率强制一部分节点贴着轮廓线(`boundary_dist < 22px`)。
所以:节点少时只有零星几个落在边缘(轮廓靠虚线框架提示);节点多时**边缘被填满,形成亮的皮层带**,
中间反而相对通透 —— 这正是真大脑的视觉特征(灰质在外、白质在内)。
这一条是让「900 条像实体」而不是「900 条像一团云」的关键。

### 框架的淡出曲线(设计细节)

- 0~140 条之间:框架与节点**同时存在**,框架当「引导线」用;
- 超过 140 条:框架完全消失,此时点云本身已足够定义形状,再留框架就是画蛇添足;
- 框架用**虚线**(每 3 个采样点画 1 段),比实线更像「蓝图」而不是「实体」,也更不容易和真实连线混淆。

### 真实使用节奏下的预估

巩固层节点数 ≈ 用户聊天天数 × 1.5(每天沉淀 1~2 条稳定记忆)。
所以:第 1 周 ~10 条(星点)、第 1 月 ~45 条(星座)、第 3 月 ~130 条(脑形初现)、半年 ~270 条(清晰)、一年 ~550 条(厚实)。
**「三个月后打开,脑形浮现」是一个真实可达的里程碑**,不是营销话术。

## 十三、落地:怎么挂进 DSH Web GUI(实现记录)

前面十二节是设计与原型,这一节是**真正接进产品**的做法,以及踩过的坑。全部零依赖、零构建步骤。

### 三层结构

```
宿主进程(src/web.ts)                浏览器
┌──────────────────────────┐
│ webServer 路由            │
│  /recall-rebuild/sea/    │──► sea.html + sea-core.js + sea-view.js + sea-app.js
│  /recall-rebuild/sea/data│──► { nodes, links, meta }  ← 巩固层投影
└──────────────────────────┘
         ▲ iframe 同源加载
┌──────────────────────────┐
│ 客户端 bundle(lib/client.js)│  注册 main 面板 + 侧边栏图标
└──────────────────────────┘
```

- **宿主侧**(`src/web.ts`):`ctx.inject(['webServer'], ...)` 注册一条 `kind:'prefix'` 的路由,前缀 `/recall-rebuild`。静态资源只放行 `/sea/` 下的文件(`resolveUiFile` 做 `path.resolve` + 前缀校验,防目录穿越),其它路径一律 404。
- **数据端点**:`GET /recall-rebuild/sea/data` 返回 `{ nodes, links, meta }`。渲染器用 `fetch('./data')` 取——相对路径正好落到这里,页面不需要知道自己被挂在哪个前缀下。
- **客户端 bundle**(`lib/client.js`):固定形状 `window.__ModuleLoader__.load({ id, factory })`,只注册两个槽位:`main`(`key = 'recall-rebuild-sea'`)与 `sidebar.panellist`(`id` 必须与 main 的 `key` 相同,否则点了没反应)。面板本体就是一个 `<iframe sandbox="allow-scripts allow-same-origin">`,把 Canvas 渲染器当普通网页跑——不和宿主的 React 版本、构建产物打架。

### 槽位注册顺序:侧边栏行必须等 main 就绪

两个槽位的 `inject` 回调谁先触发**不确定**,而宿主对「侧边栏行存在但主面板没注册」的容忍度是零——点了会选不中。`dsh-mcp-connector`(`lib/client.js:3096`)为此写了两个就绪标志 + 一个 `syncEntries()`,这里照抄同样的形状(v0.1.17 修的就是这个):

```js
var mainReady = false, panelListReady = false, entryDispose = null;
var syncEntry = function () {
  if (mainReady && panelListReady && entryDispose === null) {
    entryDispose = ctx.slots.register({ name: 'sidebar.panellist', id: PANEL_ID, order: 30, label: '记忆识海' }, SeaIcon);
  } else if (!(mainReady && panelListReady) && entryDispose !== null) {
    entryDispose(); entryDispose = null;   // 任一槽位卸载,行也跟着撤
  }
};
ctx.slots.inject('main', function () { var d = ctx.slots.register({ name: 'main', key: PANEL_ID }, SeaPanel); mainReady = true; syncEntry(); return function () { mainReady = false; syncEntry(); d(); }; });
ctx.slots.inject('sidebar.panellist', function () { panelListReady = true; syncEntry(); return function () { panelListReady = false; syncEntry(); }; });
```

这个顺序 bug 在真机上几乎不会暴露(两个槽位通常同时就绪),但一旦宿主调整装配顺序,表现是「图标在、点开空白」——比直接不显示更难查。`scripts/verify-sea.mjs` 用两个可手动触发的 deferred 回调把它钉住了:先触发 panellist 断言**没有**抢先注册,再触发 main 断言最终顺序是 `main,sidebar.panellist`。

### 模块级 `inject` 只能写硬依赖(v0.1.18 修的坑)

插件导出的 `inject` 数组是**硬依赖清单**,不是"可选依赖"的语法糖。cordis 的 `Inject.resolve()`(`cordis/lib/index.js:1490-1497`)对数组只做 `result[name] = null`,**原样把每个字符串当服务名**;随后 `Fiber` 构造里逐个 `_checkImpl(name)`,缺一个就停在 `PENDING`,整个 `apply()` 永远不执行。

v0.1.17 写了 `export const inject = ['llm', 'commands?']`,本意是"有 commands 就注册斜杠命令,没有就算了"。实际后果是插件行永远等一个叫 `commands?` 的服务,于是:

- 客户端 bundle 照常加载 → 侧边栏「记忆识海」图标**在**;
- 宿主侧 `apply()` 从未执行 → `mountSeaWeb` 没跑 → `/recall-rebuild/sea/` 返回宿主裸 **404**(不是 fence 的 403);
- iframe 加载 404 → 面板全白。

可选依赖的正确写法是**在 `apply` 里动态等待**:

```ts
export const inject = ['llm'];                    // 只留真正的硬依赖

ctx.inject(['commands'], (cctx) => {              // 服务缺席时回调不触发,静默跳过
  registerRecallRebuildCommands(cctx, store, consolidated, config, logger);
});
```

`mountSeaWeb` 里 `host.inject(['webServer', name], ...)` 一直是这个形状,只有 commands 写错了。`scripts/verify.mjs` 现在有一条回归断言:inject 数组里**不许出现任何带 `?` 的项**。

**诊断经验**:遇到"插件图标在、面板空白",先看路由返回的是 **404 还是 403** —— 403 是 fence 拦住了(配置/来源问题),404 是路由压根没挂(插件没加载)。再用"apply 里的无条件副作用"当探针(这里是 `namespaces.ensureDir()` 建的 `~/.dsh/recall-rebuild`),目录不存在即证明 `apply()` 没跑。

### 为什么面板用 iframe 而不是搬进 React

渲染器是三个零依赖 ES 模块(`sea-core.js` 纯几何 / `sea-view.js` 渲染循环 / `sea-app.js` 交互),直接当 `<script type="module">` 加载最省事。搬进 React 意味着要接宿主的构建管线、处理 React 版本、把 Canvas 生命周期塞进 hooks——收益为零,风险全在版本兼容上。iframe 的代价只是多一层文档边界,而这个面板本来就不需要和宿主通信(数据走 HTTP,不 postMessage)。

### 安全 fence(必须有)

webServer 路由对**同一台机器上的任何网页**都可见。没有 fence 时,一个恶意页面就能用 `<img>`/fetch 读走用户全部长期记忆。判定规则照抄 `dsh-mcp-connector`(`lib/web.js:116`),不自己发明:

1. `Host` 头必须存在,且是本机回环(`127.0.0.1` / `::1` / `*.localhost`)或部署声明的 `trustedHosts` 里的 authority;
2. `sec-fetch-site` 不能是 `cross-site`;
3. 带 `Origin` 时必须与 `Host` 同源。

不通过返回 403。另外:只允许 GET/HEAD(否则 405 + `allow: GET, HEAD`),响应头带 `nosniff` / `no-referrer` / 收紧的 CSP。整层**只读**,任何请求都改不了巩固层数据。

### 数据投影规则(`buildSeaGraph`,纯函数)

- 节点按 `createdAt` **升序**,超过 `sea.maxNodes` 时**丢最老的**而不是最新的——识海要能看见最近在想什么;
- 联想边去重成**无向边**(`links.json` 里 A→B 与 B→A 都存,画两遍就是重叠线);
- 边权先按 30 天半衰期衰减(`effectiveWeight`),再压到 `0.15–1`(原始 weight 是强化次数,可能远大于 1)。

投影是纯函数,所以 `scripts/verify-sea.mjs` 能直接断言,不需要起浏览器。

### 生效条件:必须重启,不能热加载

- 插件的客户端 bundle 与宿主侧路由都在**启动时**装配。装完插件后正在跑的 GUI **不会**自动加载它——实测 `unlag_refresh` 会被宿主拒绝(理由:要在右键菜单里打开 Agent 才能自己刷新)。
- 所以流程是:**装插件 → 完全退出 DSH 桌面端 → 重开 → 侧边栏出现「记忆识海」图标**。
- 判断有没有生效,不用看界面,直接打端口:生效后 `GET /recall-rebuild/sea/` 返回 200 且带 `content-security-policy` 头;未生效是裸 404(连头都没有)。
- 本机实测:DSH 桌面端的 HTTP 端口是 **55023**(127.0.0.1);同端口上 `/mcp-connector/ui/` 返回 200 可作为「这就是 GUI 端口」的对照。

### profile 是拷贝,不是软链

`dsh plugin add`(或 `package.json` 里写 `file:` 依赖 + `pnpm install`)会把插件**复制**进 `~/.dsh/profiles/<name>/node_modules/`。改完源仓库必须重新 `pnpm install` 才会同步,否则跑的还是旧拷贝。改完可以用 `diff -rq` 对比两边 `ui/` 与 `dist/` 确认一致。

### 配置

```yaml
sea:
  enabled: true       # false = 完全不挂路由(纯对话部署本就不需要)
  maxNodes: 1200      # 900 以内 Canvas 2D 稳定 60fps;超过不是画不动,而是一屏全是点没信息量
  source: raw         # 面板默认数据源:raw(底层记忆库) | consolidated(巩固层产物)
  rawLinkThreshold: 0.12   # 原始层连边阈值(字符 n-gram 余弦);越低线越密
```

- 纯函数 + 真实 HTTP 往返:`node scripts/verify-sea.mjs`(53 项断言全过:投影规则、九条信任 fence、越界路径拒绝、真实 HTTP 往返、客户端 bundle 形状与槽位注册顺序、包清单);

## 十四、双数据源:原始记忆与巩固记忆(v0.1.19)

上线后第一个真机反馈是**「面板打开了,但是空的」**。这不是 bug,是设计后果:识海当时只画巩固层,而巩固层要等「pending 碎片累积到 20 条 + 距上次巩固超 6 小时」才会跑第一轮。新装用户库里明明有几百条记忆,面板却一定是空的——**这层门槛挡在了第一次体验之前**。

修法不是降低门槛(那会让 LLM 抽象在数据不够时硬凑),而是把「看什么」和「巩固了什么」解耦:同一个面板,两路数据源。

### 唯一的技术障碍:`MemoryStore` 只能检索,不能枚举

`src/store.ts` 的 `MemoryStore` 原本只有 `search(query, limit)`。要「把库里所有点摆出来」就得给一个 query,而这里根本没有 query——拿空串硬调 `search` 只会得到一堆按奇怪规则排出来的噪声。

于是补一个**可选**原语:

```ts
export interface MemoryStore {
  ok: boolean;
  label: string;
  search(query: string, limit: number): MemoryRecord[];
  list?(limit?: number): MemoryRecord[];   // 枚举;不支持的源留空,调用方降级
  close(): void;
}
```

四个实现:prime(SQL `ORDER BY priority DESC, timestamp_str DESC`)、palace(内存数组切片)、dsh-memory(按 `updatedAt` 新→旧)、通用文本源(`makeTextStore` 里用已经建好的 `prepared` 快照直接映射)。写成可选而不是必选,是因为**枚举能力取决于底层存储形态**,不该逼所有适配器假装支持。

### 一个容易吃掉能力的坑:`combineStores` 单源分支

`combineStores` 在只有一个可用源时返回的是一个**新对象**(只转发 `search`/`close`)。加了 `list` 之后如果忘了在这里转发,表现是:多源配置下原始层正常,单源配置下原始层永远空——因为外面拿到的新对象根本没有 `list` 这个属性。这种「包装层丢方法」的 bug 不会报错,只会静默降级,所以单源分支现在显式展开:

```ts
...(typeof only.list === 'function' ? { list: (n) => only.list(n) } : {}),
```

### 原始层的边只能现算

灵枢节点目前 `edges` 全是 `[]`——原始层没有任何现成的联想边。所以 `buildRawSeaGraph` 用与检索同源的字符 n-gram 余弦自己算:

- 阈值 `sea.rawLinkThreshold`(默认 0.12),低于它的两条不连;
- **每个节点只保留最强的 topK(默认 3)条**——206 条记忆两两比较约 2.1 万次余弦(几十毫秒,可以接受),但全连会产出上万条边,画面直接糊成一团,反而看不见结构;
- 边权压到 `0.15–1`(`sim * 2.5`),与巩固层的视觉量纲对齐;
- 时间戳统一走 `toEpochMs`(灵枢的 `created_at` 是**秒**,如 `1794884879.42`;`> 1e11` 才当毫秒)。

两层的观感差异正是巩固层存在的理由:**原始层是「密度高但语义重复」的毛球**(同一件事说过五遍就是五个点),巩固层把重复收敛成一条骨架。先看毛球再看骨架,蒸馏做了什么一目了然。

### 默认值的选择

`sea.source` 默认 **`raw`**。理由是第一次打开必须**有东西看**:巩固层在冷启动时必然是空的,而空面板会被当成「插件坏了」。想只看稳定记忆的用户在面板右上角点一下即可,选择会保持到下次打开。

## 十五、3D:在 2D 之上加一维(v0.1.21)

2D 的脑剪影是**投影**出来的:点是 (u,v),深度只用来调亮度。这带来一个天花板——你永远只能从一个角度看它。用户要的是「能 360° 拖起来转」。

### 不动的部分:2D 一行没改

最省事的做法是给 3D 写一套新几何,但那会让两套画面**长得不一样**,切换时像换了个产品。所以 `placeNode3D(id, rimRatio, opts)` 完整复用了 `placeNode` 的那套拒绝采样(900 次 attempt、`insidePoly`、`boundaryDistance`、RIM_INNER/RIM_OUTER、`density` 值噪声),只在最后多算一个 z。断言 `uvMismatch === 0`(400 个 id 的 (u,v) 逐位相同)就是这条约束的守卫。

于是 `morph = 0` 时 3D 渲染器画出来的**就是 2D 那一帧**——模式切换不是两套画面互切,而是同一批点从平面「飞」进纵深。

### z 怎么来

- **皮层点**(被 `rimTaper` 压到轮廓上的那 38%):`z = sign * hw * (0.86 + 0.14 * rand)`,贴在椭球表面,所以边缘天然是立体的壳;
- **内部点**:`z = (rand * 2 - 1) * hw * cbrt(rand)`,立方根是为了**体积均匀**(直接线性取会让点挤在中面);
- `hw = depth * 0.5 * halfWidth(u, v)`,`halfWidth` 与 `placeNode` 的 spread 包络同源,所以椭球在平面上的投影与 2D 轮廓严丝合缝。

**`depth` 的语义踩过一次坑**:一开始它表示「半厚」(0.6 就是 ±0.6),结果 `brainRadius` 算出来 1.0 以上,取景被撑小、点云薄得像张纸。改成**厚度比(厚/宽)**后,0.6 意味着最厚处是宽度的 60%,`brainRadius(0.6) = 0.6933`,画面才正常。配置项 `sea.depth` 的 min/max 也因此是 0.3–0.9。

### 纵向裂:让「两个半球」看得出来

大脑最容易被识别的特征不是轮廓,是中间那道纵裂。做法是在 `placeNode3D` 末尾对 z 做一次**推开**:

```js
const gap = Math.min(fissure, hw * 0.6);
if (Math.abs(z) < gap) z = (z < 0 ? -1 : 1) * (gap + (hw - gap) * Math.sqrt(rand));
```

`sqrt(rand)` 让点落在 [gap, hw] 时靠近 gap 一侧更密(缝隙边缘更实)。`sea.fissure` 默认 `true`——关掉的话正视角就是一颗光滑的蛋。

### 相机:轨道 + 透视,但别指望透视撑起立体感

`orbitPoint(u, v, z, yaw, pitch)` 是标准轨道变换,`perspective(z, dist) = dist / max(0.15, dist - z)`。两处约束:`clampPitch` 卡在 `MAX_PITCH = 1.4835`(≈85°,防止万向节翻转),`wrapYaw` 把 yaw 折回 [-π, π](360° 旋转后数值不漂)。

**关键实测**:默认 `dist = 5.0` 时,近端与远端的透视差只有约 11%——近似正交投影。所以立体感**不能靠透视**,必须靠两条更硬的线索:

```js
const t = clamp((p.z + r) / (2 * r));        // 0 = 最远,1 = 最近
fog  = 0.20 + 0.80 * t ** 1.15;              // 亮度:远端压到 20%
size = k * (0.62 + 0.76 * t);                // 尺寸:近端 1.38 倍
```

这两个系数是调出来的:只用透视时,−27° 侧视看着像「一张贴了亮点的圆盘」;加上 fog + size 后才有纵深。想更强烈可以把 `sea.perspective` 设成 `strong`(dist 1.8,透视差约 40%),代价是边缘明显拉伸。

### 取景:按当前视角的椭球包围盒算,不是外接球

早期版本用外接球 `sc = min(w,h) * 0.86 / (2 * r)`,结果是**侧面永远比正面小一圈**,而且 3D 画面整体比 2D 小约 25%。改成按当前 yaw/pitch 投影后的包围盒:

```js
const halfW = Math.sqrt(A*A*cos2y + C*C*sin2y);
const halfH = Math.sqrt(B*B*cos2p + (A*A*sin2y + C*C*cos2y) * sin2p);
const sc = Math.min(w * 0.78 / (2 * halfW), h * 0.78 / (2 * halfH));
```

其中 `A = 0.5`、`B = BRAIN_ASPECT / 2`、`C = depth * 0.5`。取景系数 `fitSc` 每帧缓动 0.28,所以转视角时画面不会突然跳大小。

### 默认角度:−27° / 12°

正面(yaw = 0)最像脑,但完全看不出厚度;−45° 以上厚度有了、脑形散了。扫了 0 / −14 / −22 / −27 / −30 五档,−27° + 12° 俯角是「一眼是脑、又能看出是立体的」那个点,定为默认值,也是「回正」的目标值。

### 性能降级

`_trackPerf` 连续 12 帧均值 > 22ms 就升一级 LOD:0 = 全量(点和全部边)/ 1 = 只画最强 600 条边 / 2 = 只画点。降级单向、不回弹——避免在阈值附近反复抖动。拖动过程中跳过 bloom 与呼吸位移,优先保证跟手。

### 窄侧边栏

侧边栏只有 420px 时,标题、模式按钮、数据源切换、搜索框在一条线上必然打架。媒体查询 `max-width: 560px` 下改成两行:第一行标题 + 模式(靠右),第二行数据源(靠左)+ 搜索(靠右,宽度收到 132px);时间轴从右下挪到底部整宽,图例压在它下面。**媒体查询必须写在样式表末尾**——放在中间会被后面的基础规则覆盖(踩过一次,量出来 `.switch` 还在 `left: 50%`)。
